## ❌ Hard Failures（致命问题）

### 1. Entity 类使用 @Data 注解

**违规文件**:
- `ModelConfig.java:20`
- `CallLog.java:20`
- `TaskType.java:19`
- `ModelCapability.java:19`
- `ConfigAudit.java:19`

**违规代码**:
```java
@Entity
@Table(name = "ai_model_config")
@Data  // ❌ 致命错误
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class ModelConfig {
    // ...
}
```

**违反规范**: Java 开发规范 - Entity 类禁止使用 @Data

**原因**:
1. **双向关联风险**: `@Data` 生成的 `toString()` 和 `hashCode()` 会导致双向关联的无限递归
2. **延迟加载问题**: `@Data` 的 `toString()` 会触发懒加载，导致 N+1 查询
3. **性能问题**: `equals()` 和 `hashCode()` 包含所有字段，影响性能

**修改建议**:
```java
@Entity
@Table(name = "ai_model_config")
@Getter  // ✅ 使用 @Getter
@Setter  // ✅ 使用 @Setter
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class ModelConfig {
    // ...

    // 如果需要，手动实现 toString()，排除关联字段
    @Override
    public String toString() {
        return "ModelConfig{" +
                "id=" + id +
                ", modelName='" + modelName + '\'' +
                ", modelType=" + modelType +
                ", enabled=" + enabled +
                ", priority=" + priority +
                '}';
    }
}
```

**优先级**: 🔴 必须修复

**影响范围**: 5 个 Entity 类

### 2. 潜在的 N+1 查询问题

**问题位置**: `ModelSelector.java:93-103`

**问题代码**:
```java
ModelConfig bestModel = enabledModels.stream()
    .filter(model -> model.getCapability() != null)  // ❌ 可能触发 N+1 查询
    .max((m1, m2) -> {
        Integer score1 = m1.getCapability().getQualityScore();  // ❌ 每次访问都查询
        Integer score2 = m2.getCapability().getQualityScore();
        return Integer.compare(
                score1 != null ? score1 : 0,
                score2 != null ? score2 : 0
        );
    })
    .orElse(enabledModels.get(0));
```

**问题描述**:
- `ModelConfig` 与 `ModelCapability` 是 `@OneToOne(fetch = FetchType.LAZY)` 关系
- 在循环中访问 `getCapability()` 会触发 N 次额外查询
- 如果有 10 个模型，会产生 1 + 10 = 11 次查询

**修改建议**:
```java
// 方案 1: 使用 JOIN FETCH
@Query("SELECT m FROM ModelConfig m LEFT JOIN FETCH m.capability WHERE m.enabled = true")
List<ModelConfig> findByEnabledTrueWithCapability();

// 方案 2: 在 Repository 中添加方法
public ModelConfig selectByQualityPriority() {
    log.info("使用质量优先策略选择模型");

    // 使用 JOIN FETCH 一次性加载所有数据
    List<ModelConfig> enabledModels = modelConfigRepository.findByEnabledTrueWithCapability();

    if (enabledModels.isEmpty()) {
        throw new RuntimeException("没有可用的模型配置");
    }

    // 现在可以安全地访问 capability，不会触发额外查询
    ModelConfig bestModel = enabledModels.stream()
        .filter(model -> model.getCapability() != null)
        .max((m1, m2) -> {
            Integer score1 = m1.getCapability().getQualityScore();
            Integer score2 = m2.getCapability().getQualityScore();
            return Integer.compare(
                    score1 != null ? score1 : 0,
                    score2 != null ? score2 : 0
            );
        })
        .orElse(enabledModels.get(0));

    log.info("质量优先策略选择完成，模型: {}", bestModel.getModelName());
    return bestModel;
}
```

**优先级**: 🔴 必须修复

## ⚠️ Soft Warnings（警告问题）

### 1. 线程安全问题

**问题位置**: `CircuitBreaker.java:34`

**问题代码**:
```java
private final Map<Long, CircuitState> circuitStates = new ConcurrentHashMap<>();
```

**问题描述**:
- 虽然使用了 `ConcurrentHashMap`，但 `CircuitState` 内部的字段不是线程安全的
- 多线程同时调用 `recordSuccess()` 和 `recordFailure()` 可能导致数据不一致

**当前代码**:
```java
@Data
public static class CircuitState {
    private int consecutiveFailures = 0;  // ❌ 非线程安全
    private boolean open = false;
    private long openTime = 0;

    public void recordFailure() {
        this.consecutiveFailures++;  // ❌ 非原子操作
    }
}
```

**建议修改**:
```java
public static class CircuitState {
    private final AtomicInteger consecutiveFailures = new AtomicInteger(0);
    private volatile boolean open = false;
    private volatile long openTime = 0;

    public void recordSuccess() {
        this.consecutiveFailures.set(0);
        this.open = false;
    }

    public void recordFailure() {
        this.consecutiveFailures.incrementAndGet();  // ✅ 原子操作
    }

    public int getConsecutiveFailures() {
        return consecutiveFailures.get();
    }
}
```

**优先级**: 🟡 建议修复

### 3. 重复代码

**问题位置**:
- `AIModelServiceImpl.java:114-181` (executeCall 方法)
- `FallbackHandler.java:115-184` (executeWithRetry 方法)

**问题描述**:
- 两个方法都包含相似的模型调用逻辑
- 代码重复率约 70%
- 违反 DRY 原则

**建议修改**:
```java
// 提取公共方法
private AIResponse callModel(ModelConfig model, AIRequest request) {
    long startTime = System.currentTimeMillis();

    try {
        ChatClient chatClient = providerFactory.createChatClient(model);

        String promptText = request.getSystemPrompt() != null
                ? request.getSystemPrompt() + "\n\n" + request.getContent()
                : request.getContent();

        String content = chatClient.prompt()
                .user(promptText)
                .call()
                .content();

        long responseTime = System.currentTimeMillis() - startTime;

        return AIResponse.builder()
                .content(content)
                .modelUsed(model.getModelName())
                .tokensUsed(0)
                .responseTime(responseTime)
                .success(true)
                .build();

    } catch (Exception e) {
        long responseTime = System.currentTimeMillis() - startTime;

        return AIResponse.builder()
                .success(false)
                .errorMessage(e.getMessage())
                .modelUsed(model.getModelName())
                .responseTime(responseTime)
                .build();
    }
}
```
