## 📋 实施概览

### 目标
实现配置审计日志功能，自动记录 ModelConfig 和 TaskType 的 CREATE/UPDATE/DELETE 操作，并提供审计日志查询 API。

### 技术方案
- 使用 Spring AOP @Around 拦截 Controller 方法
- UPDATE/DELETE 前查询旧值
- 操作后记录审计日志
- operator 从请求头获取，缺省为"system"
- 使用 JSON 序列化对象

## 📦 类与方法设计

### 1. AuditAspect（AOP 切面）

**职责**: 拦截指定 Controller 的 CREATE/UPDATE/DELETE 方法

**关键方法**:
- `aroundCreateModel()` - 拦截创建模型
- `aroundUpdateModel()` - 拦截更新模型
- `aroundDeleteModel()` - 拦截删除模型
- `aroundCreateTaskType()` - 拦截创建任务类型
- `aroundUpdateTaskType()` - 拦截更新任务类型
- `aroundDeleteTaskType()` - 拦截删除任务类型

**处理逻辑**:
- UPDATE/DELETE: 方法执行前获取旧值
- CREATE/UPDATE: 方法执行后获取新值
- 调用 AuditService 记录审计日志
- 异常处理: 记录错误日志，不影响业务异常传播

**依赖**:
- AuditService
- ModelConfigRepository（获取旧值）
- TaskTypeRepository（获取旧值）

---

### 2. AuditService（审计服务）

**职责**: 封装审计日志持久化逻辑

**关键方法**:
- `recordAudit(tableName, recordId, operation, oldValueObj, newValueObj, operator)` - 记录审计日志
- `resolveOperator(request)` - 解析操作人（请求头优先，无则"system"）
- `serialize(valueObj)` - 对象序列化为 JSON

**处理逻辑**:
- 统一 JSON 序列化策略
- 统一 operator 获取策略
- 保存到 ConfigAudit 表

**依赖**:
- ConfigAuditRepository
- ObjectMapper（JSON 序列化）

---

### 3. AuditController（审计查询 API）

**路径**: `/api/audits`

**端点**:
- `GET /api/audits` - 分页查询审计日志
  - 参数: tableName(可选), recordId(可选), operator(可选), pageNum, pageSize
  - 返回: Result<PageResult<AuditResponse>>

**职责**:
- 参数接收与校验
- 调用 ConfigAuditRepository 分页查询
- DTO 转换
- Result 包装

## 📊 数据流

### CREATE 操作
```
用户请求 → Controller.createModel()
         ↓
AuditAspect 拦截（@Around）
         ↓
业务方法执行 → 返回新创建的对象
         ↓
AuditAspect 获取 newValue
         ↓
AuditService.recordAudit(tableName="ai_model_config", recordId=id, operation="INSERT", oldValue=null, newValue=json, operator="system")
         ↓
ConfigAuditRepository.save()
         ↓
返回响应
```

### UPDATE 操作
```
用户请求 → Controller.updateModel(id, request)
         ↓
AuditAspect 拦截（@Around）
         ↓
AuditAspect 查询 oldValue（通过 Repository.findById(id)）
         ↓
业务方法执行 → 返回更新后的对象
         ↓
AuditAspect 获取 newValue
         ↓
AuditService.recordAudit(tableName="ai_model_config", recordId=id, operation="UPDATE", oldValue=json, newValue=json, operator="system")
         ↓
ConfigAuditRepository.save()
         ↓
返回响应
```

### DELETE 操作
```
用户请求 → Controller.deleteModel(id)
         ↓
AuditAspect 拦截（@Around）
         ↓
AuditAspect 查询 oldValue（通过 Repository.findById(id)）
         ↓
业务方法执行 → 删除记录
         ↓
AuditService.recordAudit(tableName="ai_model_config", recordId=id, operation="DELETE", oldValue=json, newValue=null, operator="system")
         ↓
ConfigAuditRepository.save()
         ↓
返回响应
```

## ⚠️ 关键考虑

### 一致性保证
- **事务边界**: oldValue 获取与审计记录保存在同一事务
- **并发控制**: 明确事务隔离级别

### operator 获取策略
- **优先级**: 请求头 > 缺省值"system"
- **请求头名称**: "X-Operator" 或 "X-User-Id"

### JSON 序列化
- **统一配置**: 使用 Spring Boot 默认 ObjectMapper
- **时间格式**: ISO 8601 格式
- **空值处理**: 包含 null 字段

### 异常处理
- **审计失败**: 记录错误日志，不影响业务返回
- **序列化失败**: 记录原始对象 toString()

### 性能优化
- **审计表索引**: (tableName, recordId), (operator), (createdAt)
- **分页查询**: 限制最大页大小
- **归档策略**: 定期归档历史数据
